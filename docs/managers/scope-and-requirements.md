# 范围与需求说明

## 背景

ClassRobot 当前已经具备机器人命令、Agent 编排、Skill、Prompt、模型配置、文件处理、OCR、COS 上传、数据库持久化等能力。随着这些能力增多，只靠聊天命令和日志定位问题会越来越吃力，因此需要一个随项目本地启动的管理后台。

本后台的第一目标不是承载校园业务运营，而是帮助开发者和本地维护者管理项目自身。

## 产品定位

本地管理后台是 ClassRobot 的系统运维控制台。

它面向本机开发者、部署维护者和项目管理员，主要用于查看系统状态、调整运行配置、调试 Agent、管理 AI 资产、执行本地自动化任务。

## 设计原则

- 本地优先：默认只面向本机或受控内网访问，不按公网 SaaS 后台设计。
- 信息克制：首页只展示系统状态和待处理异常，不堆校园业务数据。
- 写操作可追踪：配置修改、重载、清理、自动化执行等动作必须有结果反馈。
- 密钥默认隐藏：API Key、COS Secret、RAGFlow Key、登录 token 等只显示掩码。
- 高风险二次确认：清理检查点、删除日志、重置 token、写入配置等动作必须确认。
- 可逐步落地：先做只读和调试，再开放可写设置和自动化动作。

## 登录方式

项目启动时生成一个后台登录 token，并输出到启动日志或控制台。

前端登录页只提供 token 输入框。登录成功后，前端保存短期访问凭证，用于后续请求后台 API。

建议策略：

- 启动 token 只在当前进程生命周期内有效。
- 支持在系统设置中手动轮换 token。
- 轮换后立即使旧 token 失效。
- 后台 API 使用 `Authorization: Bearer <token>` 鉴权。
- token 错误返回 `401`，权限不足返回 `403`。

## 用户中心范围

教师和学生不再作为独立后台模块出现，而是并入用户中心：

- 用户列表展示 `User` 基础字段和运行时角色。
- 用户详情展示平台绑定 `UserBind`。
- 如果用户有关联教师身份，作为“教师扩展信息”展示。
- 如果用户有关联学生身份，作为“学生扩展信息”展示。
- 本期只做查看、搜索、管理员标记和绑定信息查看。

## 系统设置范围

系统设置页管理项目运行配置，不承载业务规则配置。

本期建议覆盖：

- 基础设置：代理、共享目录、教师最大班级数。
- AI 设置：Google API Key、RAGFlow URL、RAGFlow Key。
- 模型设置：`llm_configs`、`llm_timeout`。
- 缓存设置：Redis host、port。
- 存储设置：COS SecretId、SecretKey、Region、Bucket、Scheme。
- 安全设置：加密盐、后台 token 轮换。
- 路径设置：data、cache、config、prompt、skill 目录，只读展示。

## 功能优先级

### MVP

- Token 登录。
- 总览页。
- 系统状态页。
- 用户中心只读。
- Agent 运行记录只读。
- Skill、Prompt、Model 只读列表。
- 日志查看。

### 第一版

- 系统设置可写。
- 模型连通性测试。
- Prompt 编辑与校验。
- Skill 重载。
- Agent 检查点清理。
- 自动化动作执行。

### 后续增强

- 管理后台操作审计。
- 后台专用配置存储。
- MCP 注册表。
- Tool Registry 管理。
- 评测集与模型成本统计。
- 外部系统集成状态面板。

## 非功能要求

- 页面首屏加载目标小于 2 秒。
- 所有写操作必须有加载态、成功态和失败态。
- 所有表格支持搜索、筛选、分页或虚拟滚动。
- 所有密钥字段默认掩码，不在列表中明文显示。
- 所有 destructive 操作必须二次确认。
- 后台接口错误需要返回稳定错误码和可读错误信息。
- 不要求移动端重度操作体验，但 375px 宽度下必须可查看和完成登录。
