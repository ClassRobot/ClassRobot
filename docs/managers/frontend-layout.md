# 前端界面布局

## 设计目标

管理后台是本地系统运维工具，视觉风格应当安静、清晰、信息密度高。

它不是展示型网站，不需要营销 hero、复杂装饰或大面积宣传内容。用户进入后台后应立刻看到系统状态、异常和可执行动作。

## 视觉基调

参考 `ui-ux-pro-max` 对运维仪表盘的建议，本后台采用数据密集、可下钻、表格优先的界面模式。

为了避免界面过于单一，配色不采用大面积紫色或深色面板，建议使用偏中性的工程控制台风格：

| Token | 建议值 | 用途 |
| --- | --- | --- |
| `--color-bg` | `#F7F8F7` | 页面背景 |
| `--color-surface` | `#FFFFFF` | 表格、工具栏、抽屉 |
| `--color-border` | `#D8DED3` | 边框和分隔线 |
| `--color-text` | `#20231F` | 正文 |
| `--color-muted` | `#6B7167` | 次要文本 |
| `--color-primary` | `#28645A` | 主操作、正常状态 |
| `--color-info` | `#3B6EA8` | 检查中、信息状态 |
| `--color-warning` | `#B7791F` | 警告状态 |
| `--color-danger` | `#C84A31` | 危险状态 |
| `--color-code-bg` | `#F0F3EF` | JSON、日志、Prompt 代码块 |

字体建议：

- UI 字体：`Fira Sans`。
- 代码和日志：`Fira Code`。

布局尺寸：

| 区域 | 桌面尺寸 | 说明 |
| --- | --- | --- |
| 顶部栏 | 48px 高 | 固定在内容区顶部 |

## 组件规范

| 组件 | 用法 |
| --- | --- |
| 状态芯片 | 展示 `ok`、`warning`、`error`、`not_configured` |
| 数据表格 | 用户、Agent、Skill、Prompt、Model 列表 |
| 工具栏 | 搜索、筛选、刷新、批量动作 |
| 详情抽屉 | 查看详情和 JSON，不打断列表上下文 |
| 分段控制 | Agent 运行记录 / 检查点 / 待确认 / 失败记录 |
| 标签页 | 系统设置中的配置分组 |
| 代码编辑器 | Prompt 内容、JSON 配置、日志 |
| 二次确认弹窗 | 删除、清理、重置 token、写配置 |
| Toast | 保存、测试、重载等短反馈 |
| 空状态 | 未配置、无记录、无异常 |

## 登录页

### 布局

- 居中窄表单，宽度 360px 到 420px。
- 标题为 `ClassRobot Manager`。
- 一个 token 输入框。
- 一个登录按钮。
- 错误信息显示在输入框下方。

### 交互

- token 为空时按钮不可提交。
- 登录中显示 loading。
- 登录失败聚焦输入框。
- 登录成功跳转 `/manager/overview`。

## 总览页布局

### 第一行

四到六个紧凑状态卡片：

- Runtime
- Database
- Cache
- Models
- Skills
- Agent

每张卡片包括状态点、主数字、简短说明和更新时间。

### 第二行

左侧是异常列表，右侧是快捷动作。

快捷动作建议：

- 测试模型。
- 校验 Prompt。
- 重载 Skill。
- 检查数据库。
- 打开日志。

### 第三行

最近 Agent 运行表格。

字段：

- Trace ID
- 用户
- 类型
- 状态
- 目标
- 开始时间
- 耗时

## 用户中心布局

### 主体

左侧主表格，右侧详情抽屉。

工具栏：

- 搜索框。
- 角色筛选。
- 管理员筛选。
- 刷新按钮。

表格行点击打开详情抽屉。

### 详情抽屉

分成五段：

- 基础信息。
- 权限信息。
- 平台绑定。
- 教师扩展。
- 学生扩展。

管理员开关放在权限信息中，并需要保存确认。

## 系统状态布局

### 卡片网格

状态卡片使用 3 列桌面布局，平板 2 列，移动端 1 列。

每个卡片结构：

- 标题。
- 状态芯片。
- 摘要指标。
- 最近检查时间。
- 查看详情按钮。

### 详情抽屉

显示完整检查结果：

- 检查项。
- 当前值。
- 期望值。
- 状态。
- 错误摘要。
- 推荐动作。

```text

| Settings Nav         | Setting Form                           |
| - 基础               | fields / validation / save bar         |
| - AI / RAG           |                                        |
| - 模型               |                                        |
| - 缓存               |                                        |
| - COS                |                                        |
| - 安全               |                                        |
| - 路径               |                                        |
+----------------------+----------------------------------------+
```

### 保存栏

当表单存在未保存修改时，底部出现保存栏：

- 已修改字段数量。
- 保存按钮。
- 重置按钮。
- 是否需要重启的提示。

### 密钥字段

- 默认显示掩码。
- 点击编辑后清空输入，要求重新填写。
- 不提供直接明文查看。

## Prompt 管理布局

Prompt 管理需要接近开发工具体验。

### 主布局

左侧文件列表，右侧编辑器。

```text
+----------------------+----------------------------------------+
| Prompt Files         | Editor                                 |
| - agent_plan.jinja   | toolbar: validate / diff / save        |
| - auto_task.jinja    | content                                |
| - extract.jinja      |                                        |
+----------------------+----------------------------------------+
```

### 编辑器功能

- 语法高亮。
- 保存。
- 校验。
- 查看差异。
- 恢复到最近备份。
- 显示关联模块说明。

## Model 管理布局

### 列表

每个模型配置显示为表格行，而不是大卡片。

字段：

- Name。
- Model。
- Base URL。
- Priority。
- Tasks。
- Multi Modal。
- Function Calling。
- Last Test。

### 编辑

模型编辑使用右侧抽屉：

- 基础配置。
- 任务标签。
- 能力开关。
- 测试按钮。
- 保存按钮。

## MCP / 集成管理布局

一期以集成状态页呈现：

- MCP 状态。
- RagFlow 状态。
- COS 状态。
- Model Provider 状态。
- 后续外部系统接入位。

对于尚未实现的 MCP 注册表，显示为 `planned`，同时给出当前架构文档链接。

## 运维调试布局

### 日志查看

日志页采用上下结构：

- 顶部选择日志来源。
- 中间日志输出区。
- 底部搜索、过滤、暂停滚动、下载。

### 自动化动作

动作列表采用表格：

- 动作名称。
- 风险等级。
- 最近执行。
- 状态。
- 执行按钮。

执行结果显示在右侧抽屉或底部输出面板。

## 响应式规则

| 宽度 | 行为 |
| --- | --- |
| 1440px 以上 | 固定侧边栏，右侧抽屉可常驻 |
| 1024px 到 1439px | 固定侧边栏，抽屉覆盖主内容 |
| 768px 到 1023px | 侧边栏可折叠，表格保留横向滚动 |
| 375px 到 767px | 底部导航或抽屉菜单，表格转简化列表 |

## 可访问性

- 所有按钮必须有可见 focus 状态。
- 图标按钮必须提供 tooltip 或 `aria-label`。
- 状态不能只靠颜色表达，需要文字。
- 表格支持键盘聚焦和回车打开详情。
- 日志和代码区域使用等宽字体，行高不低于 1.45。
- 动画遵守 `prefers-reduced-motion`。
